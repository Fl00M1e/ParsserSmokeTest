# Как запустить/собрать на macOS и Windows

Для macOS два разных пути — рекомендую начать с первого, он
надёжнее и без сюрпризов "файл повреждён":

- **Вариант 1 (рекомендуется): без сборки, просто запуск исходников** —
  никакого PyInstaller, никакой подписи, минимум точек отказа.
- **Вариант 2: настоящий `.app` через PyInstaller** — выглядит
  "солиднее", но PyInstaller на macOS капризный (вложенная
  подпись бинарников, Tcl/Tk, архитектуры) — именно с этим мы
  уже сталкивались.

Для Windows — сборка `.exe` через PyInstaller локально, без
сюрпризов, описана в конце.

## macOS, вариант 1 — просто запуск (рекомендуется)

Не заворачиваем ничего в бинарник — друг запускает обычный,
видимый Python-код напрямую через системный Python. Раз нет
скомпилированного файла — не может быть и ошибки "файл повреждён"
или предупреждениями для неподписанного бинарника.

### Что отправить

Всю папку проекта (архивом), **кроме** `.github/` и `build/` —
они не нужны для этого варианта. То есть внутри архива должно
быть: `app.py`, `parser.py`, `sheets.py`, `config.py`,
`requirements.txt`, `ParserOnSocial.command`.

### Что делает друг

1. Распаковывает архив.
2. Двойной клик по `ParserOnSocial.command`.
3. При первом запуске macOS спросит "Terminal хочет открыть
   файл, скачанный из интернета" — жмёт "Открыть"/"Allow". Это
   обычное, мягкое предупреждение, не блокировка.
4. Откроется окно Терминала, там примерно минуту скачаются
   зависимости (нужен интернет) — это происходит только один
   раз, дальше запуск почти мгновенный.
5. Откроется само приложение (окно Tkinter), Терминал можно
   свернуть — просто не закрывать его, пока приложение открыто.

### Единственное требование — Python 3

На новых версиях macOS Python не предустановлен. Если его нет,
скрипт сам покажет окно с просьбой установить и откроет страницу
загрузки — после установки нужно будет запустить `.command` ещё
раз.

## macOS, вариант 2 — настоящий `.app` через PyInstaller

Если всё же нужен полноценный `.app` с иконкой (например, чтобы
не было окна Терминала) — вот как собрать. Инструкция через
GitHub Actions (свой Mac не нужен) — в следующем разделе.

## Windows .exe — локально, у себя

Ничего особенного не нужно, у вас уже есть работающий venv-проект.

1. Откройте папку `build\` в командной строке.
2. Запустите `build_windows.bat`.
3. Готовый файл появится в `build\dist\ParserOnSocial.exe` — это
   один самодостаточный exe, его и отправляете как есть.

Учтите: `.exe` собранный на вашей Windows будет работать только на
Windows.

### Про первый запуск (SmartScreen)

Exe не подписан цифровой подписью издателя, поэтому при первом
запуске Windows Defender SmartScreen может показать синий экран
"Windows защитила ваш компьютер". Это нормально для неподписанных
программ. Решается один раз: **"Подробнее"** → **"Выполнить в любом случае"**.

## macOS .app — через GitHub Actions (свой Mac не нужен)

### 1. Разовая подготовка

1. Создайте **приватный** репозиторий на GitHub (приватный — потому что
   в проекте логика вашего парсера, не нужно светить публично).
2. Загрузите в него содержимое этой папки как есть, сохранив структуру:
   ```
   app.py
   parser.py
   sheets.py
   config.py
   requirements.txt
   .github/workflows/build.yml
   build/ParserOnSocial.spec
   build/ParserOnSocial.win.spec
   build/requirements-build.txt
   build/build_mac.sh
   build/build_windows.bat
   ```

### 2. Запустить сборку

Вариант А — вручную:
- Вкладка **Actions** в репозитории → workflow **"Build apps"** →
  кнопка **"Run workflow"**.

Вариант Б — автоматически:
- Просто запушьте изменения в ветку `main` — сборка запустится сама.

Workflow собирает **две** сборки: `.app` под Apple Silicon (arm64) и `.exe` под Windows.

### 3. Забрать готовый файл

Когда все job'ы позеленеют (обычно 2-5 минут):
- Откройте этот запуск → раздел **Artifacts** внизу страницы →
  скачайте нужное:
  - **ParserOnSocial-mac-arm64** — для M1/M2/M3/M4 маков,
  - **ParserOnSocial-win** — для Windows (сразу `.exe`).

Сборка для macOS предназначена для Apple Silicon: M1, M2, M3 и M4.

### 4. Отдать другу

Просто отправьте ему `ParserOnSocial-mac.zip` (мессенджером, диском,
как угодно) — это ОДИН файл. Он его распаковывает и получает
`ParserOnSocial.app`.

### Первый запуск на macOS

Сборка не подписывается сертификатом Apple. Если macOS покажет
предупреждение для скачанного приложения, открой `ParserOnSocial.app`
через правую кнопку мыши → **Open/Открыть**. Поддерживается только
Apple Silicon (arm64).

### Что нужно другу заранее

- **Установленный Google Chrome** (обычный, из App Store он не
  ставится — https://www.google.com/chrome/). Парсер запускает
  именно его, а не отдельный скачанный браузер. Если Chrome не
  найден, приложение теперь покажет понятное сообщение в логе
  вместо непонятной ошибки.
- Свой собственный аккаунт ON Social и доступ к своей Google
  Таблице — при первом запуске приложение создаст пустой
  `browser_profile` рядом с собой, и другу нужно будет один раз
  вручную войти в ON Social в открывшемся окне Chrome (это
  описано в README.md, раздел "Первый запуск").

## Если что-то меняется в коде

После любых правок в `app.py` / `parser.py` / `sheets.py` / `config.py`
достаточно снова запушить в `main` (или нажать "Run workflow") —
через несколько минут в Artifacts появится обновлённая сборка.
